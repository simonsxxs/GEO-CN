# 评分方法论

GEO 得分是一个 0-100 的综合分数，概括一个网站被 AI 系统发现、引用和推荐的优化程度。它由六个类目子分加权平均得出，每个子分由专门的子智能体独立评估。高分代表对生成式引擎可见性的准备充分；低分则指出具体短板，并附带按优先级排序的行动清单。

目标平台为国产 AI 搜索：Kimi、DeepSeek、豆包、元宝、通义、百度 AI 搜索。

---

## 权重表

| 类目 | 权重 |
|---|---|
| AI 引用性与可见度 | 25% |
| 品牌权威信号 | 20% |
| 内容质量与 E-E-A-T | 20% |
| 技术基础 | 15% |
| 结构化数据 | 10% |
| 平台优化 | 10% |

---

## 综合得分如何计算

每个子智能体返回一个 0-100 的子分。[`skills/geo-audit/SKILL.md`](../skills/geo-audit/SKILL.md) 中的编排器将每个子分乘以权重后求和。

**公式（来自 `skills/geo-audit/SKILL.md`）：**

```
GEO得分 = (引用性   * 0.25)
        + (品牌     * 0.20)
        + (EEAT     * 0.20)
        + (技术     * 0.15)
        + (Schema   * 0.10)
        + (平台     * 0.10)
```

**伪代码：**

```python
weights = {
    "citability": 0.25,
    "brand":      0.20,
    "eeat":       0.20,
    "technical":  0.15,
    "schema":     0.10,
    "platform":   0.10,
}

geo_score = sum(sub_scores[k] * w for k, w in weights.items())
# geo_score 落在 [0, 100] 区间
```

**得分解读（来自 `skills/geo-audit/SKILL.md`）：**

| 区间 | 评级 | 含义 |
|---|---|---|
| 90–100 | 优秀 | 极可能被 AI 引用 |
| 75–89 | 良好 | 基础扎实，仍有提升空间 |
| 60–74 | 中等 | 有一定存在感，机会明显 |
| 40–59 | 较差 | 信号薄弱，AI 系统难以引用 |
| 0–39 | 危险 | 对 AI 系统基本不可见 |

## AI 引用性与可见度（25%）

**实现位置：** [`agents/geo-ai-visibility.md`](../agents/geo-ai-visibility.md) 和 [`scripts/citability_scorer.py`](../scripts/citability_scorer.py)

### 评分器看什么

引用性子分本身是四个组件的加权综合（权重来自 `agents/geo-ai-visibility.md`）：

| 组件 | 权重 |
|---|---|
| 引用性得分 | 35% |
| 品牌提及得分 | 30% |
| 爬虫准入得分 | 25% |
| llms.txt 得分 | 10% |

**引用性评分**（`scripts/citability_scorer.py`）面向中文内容：分析页面上每个实质内容块（按标题切分、字符数 ≥20 的块），从五个维度打分。计量单位为**中文字符数（去空白）**，不再使用英文单词数。

| 维度 | 满分 | 关键信号 |
|---|---|---|
| 答案块质量 | 30 | 中文定义句式（「是指」「简单来说」「换句话说」等）；前 100 字内出现判断词或数字（推断值，原版为前 60 词）；问句标题；按中文标点切句后的短句占比；具名引用（「据…显示」「研究表明」等） |
| 自包含性 | 25 | 字数在最优区间 200-350 字（10 分，**推断值**，按 1 英文词 ≈ 1.5-2 中文字从原版 134-167 词换算）、良好区间 120-500 字（7 分）、一般区间 60-800 字（4 分）；代词密度（「它/这/那/其/该」等）低于 1%（8 分）；3 个以上具名实体（7 分，启发式识别：大写拉丁词、《书名号》、引号内容） |
| 结构可读性 | 20 | 平均句长 12-30 字（8 分，推断值）；列举连接词「首先/其次/第一/第二」等（4 分）；编号结构「1、」「第一步」等（4 分）；段落换行（4 分） |
| 数据密度 | 15 | 百分比（每个 3 分，封顶 6）；金额「元/万元/亿元/¥」（每个 3 分，封顶 5）；数字+中文量词（每个 2 分，封顶 4）；年份（2 分）；具名来源「据/根据/来自…数据/报告/研究」（每类 2 分，封顶 6） |
| 独特性信号 | 10 | 原创数据声明「我们的实测/亲测/踩坑」等（5 分）；案例举证「例如/以…为例」等（3 分）；具体工具/产品提及（2 分） |

段落得分为五个维度之和（满分 100）。页面级引用性得分为所有块的平均分。

**关于「推断值」的说明：** 中文最优长度 200-350 字等阈值是按英文原版研究结论（134-167 词）换算得来的推断值，尚未经过大规模中文实测校准，后续版本将用实测数据修正。

**爬虫准入得分**（`agents/geo-ai-visibility.md`）从 100 分起扣：
- 每屏蔽一个关键爬虫扣 15 分（国内 AI 爬虫为主，国外爬虫作对照参考）
- 每屏蔽一个次要爬虫扣 5 分
- robots.txt 未引用 sitemap 扣 10 分
- 下限为 0

**llms.txt 得分**（`agents/geo-ai-visibility.md` 和 `scripts/llmstxt_generator.py`）：
- 0 — 不存在
- 30 — 存在但格式有误
- 50 — 存在、格式正确、内容很少
- 70 — 存在、格式正确、覆盖主要内容区
- 90–100 — 内容全面，且同时提供 `/llms-full.txt`

### 好与差分别长什么样

好的 AI 引用性得分（70+）意味着：页面有多个自包含、事实密集、直接回答问题的段落；robots.txt 放行了主流 AI 爬虫；llms.txt 存在且结构良好。低分（40 以下）通常意味着内容单薄或严重依赖上下文、屏蔽了 AI 爬虫、没有 llms.txt。

## 品牌权威信号（20%）

**实现位置：** [`agents/geo-ai-visibility.md`](../agents/geo-ai-visibility.md) 和 [`scripts/brand_scanner.py`](../scripts/brand_scanner.py)

### 评分器看什么

品牌权威通过检查品牌在各平台上的存在感来评估——AI 模型在形成实体认知时会大量参考这些平台。品牌提及得分（作为上面 AI 可见度综合分的输入）由以下部分组成：

| 平台 | 可得分数 | 检查方式 |
|---|---|---|
| 百科类（Wikipedia / 百度百科） | 30 | Wikipedia API 搜索；Wikidata 实体查询（`scripts/brand_scanner.py`） |
| 行业/垂类来源 | 25 | 点评平台、媒体报道、权威行业站点 |
| 社区讨论 | 20 | 品牌讨论的存在度、时效性和情感倾向 |
| 视频平台 | 15 | 官方账号存在性和第三方视频覆盖 |
| 职场社交 | 10 | 公司主页存在性和活跃度 |

> 注：`brand_scanner.py` 当前仍以国外平台（Wikipedia、Reddit、YouTube、LinkedIn）为检查对象；国内品牌阵地（知乎、B站、公众号、CSDN、掘金）的自动检查在路线图中，当前由子智能体按同样权重人工评估。

`scripts/brand_scanner.py` 中引用的相关性数值来自 Ahrefs 2025 年 12 月对 75,000 个品牌的研究：视频平台与 AI 引用的相关性最强（0.737）；域名权重/外链的相关性较弱（0.266）。

### 好与差分别长什么样

强品牌权威得分需要：有百科词条（权重最高的信号）、社区里有成规模的讨论、视频平台上有科普或评测内容。没有百科词条、没有社区讨论、没有视频存在的品牌，无论在传统搜索里多有名，这个子分都会接近 0。

## 内容质量与 E-E-A-T（20%）

**实现位置：** [`agents/geo-content.md`](../agents/geo-content.md)

### 评分器看什么

内容智能体按 Google 的 E-E-A-T 框架评估页面。四个维度各打 0-25 分，再归一化到 0-15 参与内容分加权：

| 维度 | 满分（原始） | 检查的关键信号 |
|---|---|---|
| 经验 | 25 | 原创研究或数据、有可量化结果的案例、第一手经历、前后对比、具体人名和数字 |
| 专业 | 25 | 具名作者及资质、带履历的作者页链接、技术深度、方法透明度、Person schema |
| 权威 | 25 | 关于页质量、外部引用、行业认可、媒体报道、sameAs schema 链接 |
| 可信 | 25 | HTTPS、可见的联系方式、隐私政策、编辑规范、透明的来源标注、发布和更新日期 |

E-E-A-T 之外，完整内容分（0-100）还包含：

| 组件 | 权重 | 信号 |
|---|---|---|
| E-E-A-T（合并，归一化后） | 60% | 上述四个维度 |
| 内容指标 | 15% | 字符数分级（单薄 < 600 字；深度 6000+ 字）、近似可读性、段落长度、标题层级 |
| AI 内容评估 | 10% | 无泛 AI 腔套话、有作者声音、有原创数据 |
| 主题权威 | 10% | 内容广度（相关页面）、内链深度、枢纽-集群结构 |
| 内容新鲜度 | 5% | 发布和修改日期可见、时效性话题的更新近度 |

### 好与差分别长什么样

70+ 分要求：有可验证资质的具名作者、原创数据或案例、透明的来源标注、HTTPS、内容超出对主题的浅层覆盖。30 分以下通常意味着：没有作者署名、没有外部来源、没有 HTTPS、内容任何人都能写出来、毫无行业积累。

## 技术基础（15%）

**实现位置：** [`agents/geo-technical.md`](../agents/geo-technical.md)

### 评分器看什么

技术智能体从九个加权组件计算得分：

| 组件 | 权重 |
|---|---|
| 服务端渲染 / JS 依赖 | 25% |
| Meta 标签与可索引性 | 15% |
| 可抓取性（robots.txt、sitemap） | 15% |
| 安全响应头 | 10% |
| Core Web Vitals 风险 | 10% |
| 移动端优化 | 10% |
| URL 结构 | 5% |
| 响应头与状态码 | 5% |
| 附加检查 | 5% |

服务端渲染权重最高，因为 AI 爬虫（国内国外皆然）普遍不执行 JavaScript。需要 JS 才能渲染正文内容的页面，对 AI 爬虫来说等于不存在，内容写得再好也没用。

安全响应头扣分（来自 `agents/geo-technical.md`）：
- 无 HTTPS：-30 分
- 无 HSTS：-10 分
- 无 CSP：-10 分
- 无 X-Frame-Options：-5 分
- 无 X-Content-Type-Options：-5 分
- 无 Referrer-Policy：-5 分
- 无 Permissions-Policy：-3 分

Core Web Vitals（LCP、INP、CLS）通过静态 HTML 分析评估为低/中/高风险。智能体会明确注明：真实测量需要现场数据（PageSpeed Insights 或 CrUX）。

### 好与差分别长什么样

高技术分要求：完整的服务端渲染、放行 AI 爬虫的规范 robots.txt、被引用的 XML sitemap、带 HSTS 的 HTTPS、干净的 meta 标签。危险级发现是任何纯客户端渲染的 SPA——不执行 JavaScript 时 HTML 主体为空，这种状态下任何内容优化都无法帮助 AI 发现。

## 结构化数据（10%）

**实现位置：** [`agents/geo-schema.md`](../agents/geo-schema.md)

### 评分器看什么

schema 智能体检测页面源码中的 JSON-LD、Microdata 和 RDFa 结构化数据，按十个组件评估完整度：

| 组件 | 满分 | 标准 |
|---|---|---|
| Organization / LocalBusiness | 20 | 存在（10 分）；sameAs 链接 3 个以上平台（20 分） |
| Article / 内容 schema | 15 | 存在（8 分）；作者为 Person 对象（12 分）；有 dateModified（15 分） |
| 作者 Person schema | 15 | 存在（8 分）；有 sameAs（12 分）；有 jobTitle 和 knowsAbout（15 分） |
| sameAs 完整度 | 15 | 1-2 个平台（5 分）；3-4 个平台（10 分）；5 个以上平台含百科（15 分） |
| speakable 属性 | 10 | 存在且指向内容区块（10 分） |
| BreadcrumbList | 5 | 存在且有效（5 分） |
| WebSite + SearchAction | 5 | 存在且有效（5 分） |
| 无废弃 schema | 5 | 不含 HowTo（2023 年 9 月移除）或 SpecialAnnouncement |
| JSON-LD 格式 | 5 | 全部 schema 用 JSON-LD 而非 Microdata 或 RDFa |
| 校验（无错误） | 5 | 全部 schema 通过语法和属性校验 |

智能体还会标记由 JavaScript 注入、而非存在于初始 HTML 响应中的 schema——AI 爬虫不执行 JavaScript，会完全漏掉这些 schema。

检查的废弃和受限状态（来自 `agents/geo-schema.md`）：
- HowTo：2023 年 9 月起从 Google 富媒体结果中移除
- FAQPage：2023 年 8 月起仅限政府和卫生权威机构站点
- SpecialAnnouncement：已废弃

### 好与差分别长什么样

高 schema 分要求：Organization schema 的 sameAs 链接至少 5 个平台（含百科）、所有内容作者有正确嵌套的 Person schema、Article schema 带 dateModified、全部 schema 以服务端渲染的 JSON-LD 交付。接近零分意味着完全没有结构化数据，也就移除了给 AI 模型的一切显式实体链接信号。

## 平台优化（10%)

**实现位置：** [`agents/geo-platform-analysis.md`](../agents/geo-platform-analysis.md)

### 评分器看什么

平台智能体分别评估各 AI 搜索平台的就绪度并汇总。目标平台为国产 AI 搜索：Kimi、DeepSeek、豆包、元宝、通义、百度 AI 搜索。每个平台有自己的子分拆解：内容结构（问句标题、直接答案段落、对比表格）、来源权威信号、技术信号（对应爬虫的 robots.txt 放行情况）、实体识别信号（百科词条、sameAs schema）等。

### 好与差分别长什么样

强平台分要求：通过其他类目里出现的爬虫准入和实体识别检查，外加平台特定的结构模式——问句标题和直接答案段落、百科存在感、社区平台存在感。由于这个类目与其他多个类目有重叠，在 AI 引用性和品牌权威上得分高的站点，这里通常也不会差。

## 注意事项

**确定性评分 vs LLM 判断评分。** 引用性评分器（`scripts/citability_scorer.py`）和 llms.txt 校验器（`scripts/llmstxt_generator.py`）是完全确定性的：给定同样的 HTML，每次返回同样的数值结果。品牌权威、内容 E-E-A-T、技术、Schema、平台得分由 LLM 子智能体按文档化的规则产出，属于有引导的评估而非可复现的计算。同一 URL 跑两次，LLM 判断的类目可能有小差异。

**权重是主观设定的。** 25/20/20/15/10/10 的权重分布反映的是工具作者写作时对各类目相对重要性的判断，并非来自对照研究，会随 AI 搜索平台演变而调整。

**是诊断工具，不是保证。** GEO 得分是诊断仪器。高分改善了被 AI 引用的结构条件，但不保证任何特定 AI 系统一定会引用或推荐该站点。AI 模型行为取决于许多本工具之外的因素，包括模型训练数据、提问措辞和竞品内容。

**Schema 校验是结构性的，不是语义性的。** schema 智能体检查 JSON-LD 语法有效、使用公认的 Schema.org 类型和属性、包含必填字段。它不验证取值是否准确、所描述的实体是否匹配真实的组织或个人。通过校验的 schema 块仍可能包含错误信息。

**llms.txt 是新兴标准。** `scripts/llmstxt_generator.py` 和 `agents/geo-ai-visibility.md` 引用的 llms.txt 规范尚未被 AI 爬虫普遍采纳。目前其存在与否不保证任何具体的爬虫行为。
